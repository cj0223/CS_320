Module Eight Reflection
How can I ensure that my code, program, or software is functional and secure?
Ensuring functionality and security starts with clear requirements and thorough testing. Automated unit tests verify that each method behaves correctly and consistently, even as the code evolves. Validating all user input, enforcing constraints, and testing failure conditions help prevent unexpected behavior and reduce vulnerabilities. Secure software also requires defensive coding practices, careful handling of data, and regular reviews to catch issues early.

How do I interpret user needs and incorporate them into a program?
Interpreting user needs begins with understanding what the user is trying to accomplish and translating those requirements into specific rules. In Project One, the Contact Service requirements defined exactly how long each field could be and what values were invalid. By turning those rules into code and automated tests, I ensured the program behaved the way the user expected. Testing based on requirements helps clarify edge cases and prevents assumptions.

How do I approach designing software?
I approach software design by breaking the problem into small, manageable components. For CS 320, I built the Contact class first, then the ContactService, and finally the test classes to validate each part. I focus on modular design, predictable behavior, and clear responsibilities. Automated testing is part of the design process, not something added at the end. This approach makes the software easier to maintain, easier to test, and more adaptable when requirements change.
